# The v31 catalogue, next to the classic one

Habbo r31's catalogue (`hh_cat_new`: a tree index with coloured nodes, icons and folders, a 3x3 product strip, the
old special pages wrapped) and the classic one (`hh_cat_code`) are both in the hotel since 2026-11-27 (branch
`feature/catalogue-choice`, which reapplied the parked v31 work onto master). Odin answers each client in its
catalogue's format; the deploy files and the starting tree are in the workspace's `prod-staging/catalogue-choice/`.

## Who gets which

- `Services/CatalogueChoice.cs`: a player who picked r31's catalogue (`users.catalogue_v31`, profile tab "Katalog",
  `/profile/catalogue`) gets `keplercms:catalogueV31:vars` as the client's external variables (Shockwave's `/client`
  and the web client's `/client/web`): `gamedata/external_vars_v31.php`, a wrapper of `external_vars.php` that swaps
  `hh_cat_gfx_all`, `hh_cat_code(_amount)` and `hh_dynamic_downloader` for r31's and adds furnidata/productdata.
  Everyone else gets the usual file. The choice applies from the next time the hotel opens.
- Setting `cms.catalogue.choice` (Housekeeping > Settings): `off` (everyone has the classic one, whatever they picked),
  `staff` (ranks with `fuse_catalogue_administrator`) or `everyone`. Without `keplercms:catalogueV31:vars` nobody can
  pick it. Migration `sql/migrations/2026-11-27_catalogue_choice.sql` (column + setting, `staff`).

## Maintaining it (Housekeeping > Admin tools > Catalogue)

- Index tab, **Classic catalogue**: the classic list, drag to reorder (`order_id`). Folders don't exist there.
- Index tab, **v31 tree (folders)**: the r31 tree; drag a page onto another's top or bottom edge to put it before or
  after it, onto its middle to put it inside (any page can hold pages, as Trax holds its genres). One save writes
  every page's `parent_id` and `tree_order` (Odin `update.1.53.sql`); the classic order isn't touched. It also says
  how many players picked r31's catalogue and who may pick it.
- Page tab: the node's colour and icon, its parent ("Under") and a v31 layout override; **New folder**.
- The preview's **v31 catalogue** switch draws the page as r31's catalogue shows it (below).
- Publish also lists the page images that come from the image library (`catalogue_library_images`): r31's catalogue
  asks for `<name>.gif`, so Odin sends those names with `_da`.

## What the v31 parts are

- `Controllers/GameDataController.cs`: `GET /gamedata/furnidata` and `/gamedata/productdata`, the files the v31
  catalogue downloads (`furnidata.load.url`, `productdata.load.url`), built from `items_definitions` and
  `catalogue_items`: ISO-8859-1 Lingo list lines, CORS, cached 10 minutes, cleared on Publish. No file extension,
  so Cloudflare doesn't cache them.
- The catalogue editor (`/housekeeping/catalogue`): per page the v31 tree's parent ("Under"), node colour and icon
  (r31 graphics in `wwwroot/housekeeping/catalogue/v31/colour_*.png`, `icon_*.png`), and a v31 layout override;
  **New folder** (a page without a layout: only the v31 tree shows it); the Index tab shows the tree.
- Productdata names an offer like Odin does: the sale code, or `<sale code>_<item id>` when several catalogue items share
  it (the client groups offers by name; all wallpapers would be one product, see Odin's `tools/catalogue-v31/README.md`).
- Publish fills `catalogue_library_images` (page images that come from the image library: Odin sends them to the
  v31 catalogue as `name_<language>`).
- Needs the database columns from Odin's `update.1.40.sql` (`catalogue_pages.parent_id/icon/colour/layout_v31`,
  `catalogue_library_images`). They are still on prod; the reverted code ignores them.

## The v31 preview

The editor's preview has a **Web client (v31)** switch (remembered per browser) next to "2x". With it on, the preview
draws the v31 catalogue the web client would run: its window and purse line ("<balance> <credits>", no pixels), the
tree (folders, colours, icons, arrows; clicking a node opens it and selects it in the editor, the open page's
ancestors open by themselves), default-class pages through `ctlg_<v31 layout>` with the `layout.fields.*` mapping
(same as Odin's `CataloguePage.getV31Texts/Images`), the 3x3 product strip (picking a product hides the badge, shows
the price box, the large preview, name, description and price), and the old special pages (plasto, spaces, trophies,
pets, recycler, soundmachine, purse) through the existing page code on v31's copies of their windows. Without the
switch the preview is the Shockwave catalogue as before (folders left out of its index).

- Assets: `tools/catalogue/build_assets.py --v31 <dump of hh_cat_gfx_v31> <decompiled>` writes `v31/layouts.json`
  (windows, members, member sizes), `v31/members/`, `v31/images/`. The dump comes from habbo-vibe-playground's
  `node out/cli/dumpCast.js hh_cat_gfx_v31.cct <dir>`. The tree, arrow, icon and strip bitmaps are written opaque
  (the dump keeps 32-bit members' raw alpha byte, junk on the arrows; Director ignores it without useAlpha).
  `overrides_v31/` has `stripitem.basic.bg.unselected` (JPEG in the cast, saved from the running client); the old
  build's `overrides/` are used too.
- Code: `catalogue-view.js` `renderV31`, `fillV31`, `drawStrip`, `selectV31`, `drawTree`; it follows hh_cat_new's
  Catalogpage Default Class, Product Strip Default Class, Treeview Node Renderer Class, Catalogue Interface Class.
